## Exact replacement and compatibility contract

- Next16.4.1 -> 16.4.6, with @next/env and SWC platform packages16.4.6.
- Existing Next root adapter1.0.0 -> 1.1.0: preserve its single-pattern,
  onlyDirectories contract/guards while replacing tinyglobby with glob14.0.6.
- New private @ai-ip/ts-project-glob-adapter1.0.0 supplies only globSync and
  isDynamicPattern for the two pinned TypeScript consumers. The tinyglobby npm
  alias resolves to this clearly named owned implementation, not an upstream
  tinyglobby release. No vulnerable package is merely relabeled or retained.
- The one necessary new engine is official glob14.0.6. It resolves minimatch11.0.9,
  minipass7.1.3, path-scurry3.0.0 and its lru-cache11.5.3; brace-expansion5.0.13
  and balanced-match4.0.4 support that matcher. Shared
  @isaacs/nonrecursive-glob-match1.0.3 -> 1.1.0 is deduplicated for that graph.
  No new network service or product runtime feature is added.
- eslint-config-next/@next plugin16.3.8, TypeScript-ESLint8.70.1, resolver3.10.1,
  ESLint9.39.5 and the existing estree minimatch11.0.1 override stay pinned.
  Their HIGH propagated paths disappear through engine removal. Updating their
  rules/configs unnecessarily would expand the change and invalidate the frozen
  original lint baseline.

Node24.18.0 is the existing tested runtime. Its core fs.glob lacks the required
dot:true contract: an actual probe omitted hidden files. The official glob
engine supports the necessary dot, ignore, absolute and symlink semantics. Both
adapters use synchronous ESM (also require-compatible on Node24); no custom
regular-expression glob engine or copied third-party parser is introduced.

The TS adapter accepts strings/bounded arrays and the actual consumers' cwd,
absolute, dot, expandDirectories and ignore options. Unknown options reject;
there are no empty-result fallbacks for unsupported APIs or access failures.
Default only-files/follow-link behavior, directory includes, ignored subtrees,
spaces/Unicode and project patterns are tested. Pattern length/operator/brace
expansion and array limits bound parsing before the matcher is entered.
Output path sets are deduplicated and sorted; old filesystem-dependent traversal
order was not an API promise. Actual estree project-pattern precedence remains
unchanged and is exercised through its installed implementation.

The Next adapter retains every prior complexity guard and its deterministic
directory ordering. The original dep-001-lint-baseline.json is unchanged,
including 25 configurations, negative rule diagnostics and official plugin
source hashes. No eslint rule/ignore or security gate is removed or weakened.
