## C2 dependency proposal

The C1 specification and implementation are merged; postmerge CI remains failed from artifact quota, so C1 closeout is pending. C2 would consume only a current trusted custody revision and invoke P2-002 reconstruction, P2-003 specification, P2-004 supported-Claims checks, P2-005 seven-original assembly and P2-006 four-file render. Its review UI must show missing/unsupported content and require a Human checkpoint; artifact downloads must verify current session, revision and manifest. A future authenticated browser route needs a separate security decision. The C2 Draft is a contract, not executable integration.

## D offline harness boundary

Default `OFFLINE_ONLY`, fail closed even when an environment key happens to exist. Inspect installed OpenAI SDK import/version compatibility, prompt/schema references, provider runtime configuration shape, model identifier **syntax only**, timeout/retry limits and output/token caps without constructing any SDK client. Report credential state as `PRESENT`/`ABSENT` without value, prefix, length or fingerprint. Use test-only tripwire to deny non-loopback egress and client construction. Machine-readable result includes candidate Git SHA, each check `PASS`/`BLOCKED`/`NOT_RUN`, zero unexpected attempts, and a readiness status. `READY_FOR_AUTHORIZED_PROVIDER_SMOKE` means offline prerequisites only; model entitlement remains `UNVERIFIED`. See the [future funded-pilot checklist](../operations/PREAPI-001-funded-pilot-checklist.md). Future live mode requires a separately authorized kill switch, max requests/tokens/USD, verified pricing, timeouts, retry ceiling and hard stop before any client is created. No such live mode exists now.

## E fixture evaluation boundary

Use the six Human-accepted, unchanged gold packages in `eval/semantic/v1/gold/` and existing evaluator tests to validate parsing, scoring arithmetic, reporting and refusal/missing-data labels with synthetic fixture judgments only. Record fixture provenance and actual case/item totals. Do not rewrite accepted gold, download full papers in CI, treat mock scores as model outcomes, or change `PRODUCT_RUNTIME=NOT_DETERMINED`. Funded evaluation still requires a separate provider/account/model, data-rights and budget decision.

## Exit gates

Zero-cost readiness requires postmerge-verified C1 custody implementation, separate C2 synthetic flow with four verified outputs, D offline checker, E fixture scorer validation, exact-SHA review/CI/merge receipts and unchanged deployment/security boundaries. It does **not** establish `LIVE_PROVIDER_VALIDATED`, semantic acceptance, patentability, filing readiness or production release.
