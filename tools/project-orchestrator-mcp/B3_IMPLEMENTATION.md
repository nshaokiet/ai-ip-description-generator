  through the same-task persisted pointer; validates all typed verification chains;
  derives terminal level, revocation, superseded history and current applicability.
- Required/observed gate entries expose evidence IDs, exact targets, levels,
  required/not-required/unresolved status, missing/stale/revoked evidence, provenance,
  Human gates, fresh-check requirements and separate blocker lists.
- Provisional readiness requires recorded task/freeze authorization, current frozen
  spec/F identities, all current CI observations SUCCESS, required independent
  read-only PASS reviews, no unresolved stop/scope/confidentiality condition and
  explicitly recorded Human exception requirements. All merge-critical revocations
  and malformed verification chains fail closed.
- R3/R4 require both review streams. R0–R2 use explicitly recorded Security policy;
  unknown conditional policy is unresolved. Optional Security with an unresolved
  finding still stops readiness, including during re-review. Newer pending attempts
  cannot reuse old PASS. CI/reviews never select a different SHA to satisfy F.
- `metadata_json.merge_policy` in the existing exact task-authorization chain carries
  recorded scope/safety/exception/conditional-review context and optional expected
  repo/PR identity. No schema change or competing persistence model is introduced.
  See package README for the strict contract and synthetic example.
- §18.1 source responsibility matrix is enforced as an empty accepted-adapter set:
  **no authoritative verifier adapter is available**. Supplied VERIFIED fields,
  verifier/source labels and timestamps cannot grant authority.
  `authoritative_merge_eligible=false` always, with explicit capability/source/fresh
  check blockers. This is the allowed trust-based B3 rollout, not an activated merge
  permission. No source adapter, network/credential scope or fake identity was added.
- `project.get_merge_gate` is the only added public MCP tool (25 total).
  V2 `get_state` includes its snapshot result and performs no V2 lease/evidence
  mutation. Expiry recovery remains on existing action/next-task paths. V1 read
  recovery and returned V1 behavior remain compatible; V1 gate returns NOT_APPLICABLE.
- MERGE_RESULT is reconstructed as post-merge history only and is not required
  pre-merge. Gate computation never merges/pushes, writes evidence, records merge
  completion, authorizes Human decisions or enrolls/activates tasks.
